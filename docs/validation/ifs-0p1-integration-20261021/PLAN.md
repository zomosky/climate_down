# IFS 0.1° Google 接入与最近一天验收

目标：新增独立 `ifs-hres-0p1`，沿用 manifest → 中国区 Zarr → zrread → watcher 流程，实测原生全时效下载、切片、查询及总耗时。现有 `ifs-hres` 0.25° 配置、数据和运行参数不变。

1. 核对 241 资源、Google 原生目录、服务器现场文件；新增源及全时效服务器作业。按用户确认，仅验收已完整发布的 20261020 12z（85 个原生时效）。
2. 新增 restorage 独立适配器和 2-worker 配置；新增继承 IFS 语义的 zrread profile。监控保持磁盘自动发现，通过新 reader profile 暴露元数据、变量与 API。既有权重层沿用网格无关的对齐机制。
3. 有针对性验证注册、命名、辐射差分/重采样与新源隔离；以文件 SHA-256 和备份清单部署最小增量，保留服务回滚镜像。
4. 用真实原生全时效数据完成最终验收：manifest/每文件 SHA-256、Zarr 全字段/原生时效/0.1° 网格、原生缺失、站点/区域/网格/API/NetCDF 和监控。记录下载、切片、读回、服务可见及全程耗时，保留日志、结果和校验和。
5. 验收通过后增加独立 00/12 UTC 下载与切片调度，纳入补录/重启恢复；核对旧 0.25° 的配置哈希和真实查询未变。

主要失败方式：两份物理文件缺一份或偏移混用；0p1 首发前的起报被错误补录；混合步长/原生缺项被补值；0.1° 处理内存超限；服务镜像漏带新 profile；发布早于完整读回；部署覆盖服务器无关改动。分别由既有 split 测试、起始起报边界测试、原生元数据比对、2-worker/内存余量、镜像文件哈希及真实 API 验收覆盖。

生产限制：下载 8 路且单起报并发，重整 2 worker、单起报顺序；不改变两个长期容器的现有限额，不提交或推送 Git。网络仅从 Google 取公开数据。
